# YOLO Vision Toolkit

**YOLO 객체 탐지 데이터셋을 만들고 · 라벨링하고 · 학습하고 · 검증하는 웹 기반 올인원 툴킷.**

원본 이미지·영상만 있으면 브라우저 안에서 데이터셋 구축부터 모델 학습, 성능 비교까지 한 사이클을 전부 돌릴 수 있습니다. 별도 라벨링 툴이나 학습 스크립트 없이 하나의 앱에서 끝납니다.

## 1. 이 프로젝트는 무엇인가

YOLO 모델을 실제로 쓰려면 늘 같은 반복 작업이 필요합니다 — **데이터를 모으고, 박스를 그리고, 데이터셋으로 묶고, 학습을 돌리고, 결과를 확인하고, 다시 더 좋은 모델로 라벨링을 반복.** 이 툴킷은 그 전체 루프를 웹 UI 하나로 묶은 도구입니다.

핵심 아이디어는 **자기 강화 루프(self-improving loop)** 입니다:

> **라벨링 → 사람 검수 → 데이터셋 내보내기 → 학습 → 학습된 모델로 다시 라벨링 →** (반복)

모델 1~N개를 앙상블로 돌려 자동으로 초벌 라벨을 만들고(사람은 검수·수정만), 그 데이터로 새 모델을 학습하면, 그 모델이 다음 라운드의 자동 라벨링을 더 정확하게 해줍니다. 라운드를 돌수록 라벨 품질과 모델 성능이 함께 올라갑니다.

- **작업 단위는 "프로젝트"** — 프로젝트마다 이미지·라벨·클래스·모델·학습 기록이 독립적으로 관리됩니다.
- **기준 모델은 `yolo26n`** — 모델 레지스트리에서 공식 모델(yolo26 / yolo12 / yolo11 계열, n~x 사이즈)을 바로 내려받거나, 직접 학습·보유한 `.pt`를 업로드해 쓸 수 있습니다.
- **로그인/인증 없음** — 신뢰할 수 있는 네트워크 안에서 쓰는 내부 도구를 전제로 설계되었습니다. ([보안 주의](#보안-주의) 참고)

## 2. 전체 워크플로우

```
 ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
 │ 가져오기  │→ │ 오토라벨링 │→ │  검수     │→ │  나누기   │→ │   학습    │
 │ 영상/     │   │ 앙상블    │   │ 박스 편집  │   │train/val/ │   │Ultralytics│
 │ YOLO zip  │   │ 추론      │   │ 검수완료✓  │   │  test     │   │ 실시간차트 │
 └──────────┘   └──────────┘   └──────────┘   └──────────┘   └────┬─────┘
       ▲                                                          │
       │                                                          ▼
       │            ┌──────────┐         ┌──────────────────┐  ┌──────────┐
       └────────────│  검증     │←────────│  모델 레지스트리  │←─│ best.pt  │
       재라벨링에    │Crop /    │         │ 학습 결과 등록    │  │ 등록      │
       더 좋은 모델   │Benchmark │         └──────────────────┘  └──────────┘
                    └──────────┘
```

**이 전부가 데이터셋 하나 안에서 일어납니다.** 학습은 그 데이터셋을 바로 먹으므로 내보내기를
먼저 할 필요가 없고, 내보내기는 **밖으로 반출할 때만** 씁니다.

홈에서 **두 공간**이 갈립니다. 축이 다르기 때문입니다 — 종목(농구·야구)은 프로젝트가, 연구는 별도 공간이 갖습니다.

```
홈
├ 🔬 Lab (연구실)      basketball-adaptive-crop        ← 연구 하나
│     └ 크롭 · 크롭 이력
└ 🎓 Studio (학습실)   basketball · baseball · …       ← 도메인마다
      └ DataSet · Training · Models
```

두 공간은 **모델 풀만 공유**합니다. 영상은 각자 갖습니다 — 학습용 영상(장면 샘플)과 연구용 영상(크롭할 경기)은 용도가 달라 실제로 다른 영상입니다.

**개수가 다릅니다.** 학습실 프로젝트는 도메인마다 늘어나지만, **연구실은 연구 하나**입니다. 지금은 `basketball-adaptive-crop` 하나뿐이고, 야구를 하게 되면 `baseball-adaptive-crop` 이 생기는데 그건 패키지부터 다르고 파이프라인이 아예 달라질 수 있어 **화면에서 만들어 낼 수 있는 물건이 아닙니다** — 코드로 들어옵니다. 그래서 연구실에는 생성·삭제·이름변경이 없습니다.

학습실 사이드바는 **DataSet · Training · Models** 셋뿐입니다. 업로드·클래스·내보내기가 독립
화면이던 시절이 있었지만, 전부 **데이터셋 안**으로 들어갔습니다 — 클래스도 검수도 분할도
내보내기도 그 데이터셋의 일이지 프로젝트의 일이 아니기 때문입니다.

**데이터셋끼리는 아무것도 공유하지 않습니다.** 같은 영상으로 두 데이터셋을 만들려면 두 번
추출합니다. 대신 한쪽을 마음대로 고쳐도 다른 쪽이 흔들리지 않고, 삭제도 통째로 깔끔합니다.

## 3. 기능 한눈에 보기

| 영역 | 기능 | 요약 |
|---|---|---|
| **프로젝트** | 프로젝트 관리 | 도메인(농구·야구) 단위 격리. 카드에 데이터셋/이미지/검수완료 수 |
| **데이터셋** | 데이터셋 관리 | 만들고 · 이름 바꾸고 · 통째로 지운다. 이미지·라벨·클래스·검수·분할을 전부 자기가 가짐 |
| **데이터 입력** | 영상 프레임 추출 | 동영상 → 프레임 샘플링. FPS·최대 프레임·구간 트림·근접 중복 제거. **원본 프레임 그대로**, 추출 후 영상은 버림 |
| | 기존 데이터셋 가져오기 | YOLO zip(이미지+라벨+data.yaml)을 라벨째. 클래스 병합·id 재매김. **검증된 데이터로 표시하면** train/val/test 폴더가 그대로 분할이 됨 |
| **라벨링** | 오토라벨링 (앙상블) | 모델 1~N개, **모델마다 Full scan / Tiled** 선택 → 타일 경계 병합 → Weighted Box Fusion → 자동 박스 |
| | 라벨 에디터 | Konva 기반 박스 그리기/편집. 키보드 단축키, 확대/이동, 복사/붙여넣기, 실행취소 |
| | 클래스 관리 | 데이터셋 화면의 **Classes** 모달에서 추가·이름변경·삭제. 클래스별 박스 수 표시, 색상 자동 배정 |
| | 검수 플로우 | 이미지별 "검수 완료" 체크(미검수/검수완료 탭), 네거티브(빈 라벨) 샘플 표시 |
| **분할** | 비율 나누기 | 검수완료를 train/val/test 로. 기본 8:1:1, **미할당만** 배정해 기존 배정을 보존 |
| **내보내기** | 3종 zip | 학습(train+val) · 테스트(test) · 원본(검수완료 전부). 하드링크라 디스크는 한 벌 |
| **학습** | 학습 실행 | **데이터셋을 직접** + 베이스 모델 + 하이퍼파라미터 → Ultralytics 학습. 증강 옵션. **타일링 옵션**으로 train/val 만 타일로 잘라 학습 가능(test 는 원본 유지) |
| | 실시간 모니터링 | 에폭별 mAP/loss/LR 차트, 클래스별 지표, 결과 이미지, 실시간 로그 |
| | 학습 이력 | 프로젝트별 전체 학습 기록, 상태 배지, 중지/삭제 |
| **모델** | 모델 레지스트리 | 공식 모델 다운로드 · `.pt` 업로드 · 학습결과 등록 · 다운로드 |
| **연구실** | Crop | 영상·모델·노브·크롭 크기·출력 옵션을 한 화면에서 정하고 실행. 런 하나가 crop.json·가로 영상·세로 크롭 **셋을 다** 냄 (좌표 계산은 `adaptive-crop` 패키지) |
| | 영상 아카이브 | 크롭할 원본을 Crop 화면에서 바로 올리고 지움. 프레임 추출 없이 그대로 보관 |
| | Crop Runs | 크롭 실행 이력 — 상태·커버리지·설정이 남고 **만료 없음**. 런 복제로 모델만 바꿔 재실행 |
| **검증** | Benchmark (모델 벤치마크) | **데이터셋의 test 분할**을 정답 삼아 여러 모델을 채점. P/R/F1·mAP 는 물론 곡선·크기별 AP·혼동행렬·추론 속도까지 TensorBoard 같은 화면(레일 + Scalars/Curves/Matrix/Images 탭)에서 본다. **모델마다 Full scan / Tiled** 를 골라 배포 방식 그대로 겨룸. 실행 이력이 남고 **만료 없음** (Models 페이지) |
| **CLI** | 오토라벨링 CLI | 웹 없이 커맨드라인으로 폴더 단위 앙상블 라벨링 |
| **공통** | 전역 작업 인디케이터 | 영상 가져오기·오토라벨링 진행률을 우상단 패널에서 통합 표시·취소 |

## 4. 기능 상세 설명

### 홈 · 학습실 프로젝트 (Home / Studio)
- 홈은 **문 두 개**뿐입니다 — 연구실(Lab)과 학습실(Studio). 목록은 각 공간에 들어가서 봅니다.
- 학습실에서 프로젝트를 만들거나 엽니다. 각 프로젝트 카드는 이름·생성일과 **데이터셋 / 이미지 / 검수 완료** 3가지 라이브 통계를 보여줍니다(그 프로젝트 데이터셋들의 합).
- `⋮` 메뉴에서 프로젝트를 삭제하면 그 프로젝트의 모든 데이터(데이터셋·모델·학습기록)가 함께 삭제됩니다.

### 데이터셋 목록 (DataSet)
카드 목록 + **추가** 버튼. 이름을 정하면 그 데이터셋 페이지로 들어갑니다. 카드에는 이름·생성일과
**미검수 / 검수완료 / train·val·test** 수치가 보입니다. 이 수치는 저장된 값이 아니라 서버가 파일을
세어 그때 만든 것이라, 밖에서 무슨 일이 있었든 항상 실제와 맞습니다.

### 데이터셋 상세
가져오기부터 내보내기까지 한 화면에서 끝납니다. 상단 수치는 흐름 순서 그대로입니다.

```
미검수 10   검수완료 23   ├ 미할당 9 · train 12 · val 1 · test 1
```

**가져오기**(모달) — 미검수 탭의 `Import images` 버튼. 두 가지입니다.
1. **Video** — 동영상에서 프레임을 뽑습니다. 결과는 **전부 미검수**입니다.
   - **FPS**(초당 추출 프레임 수, 원본 fps와 무관), **최대 프레임 수**, **근접 중복 프레임 제거(dedup)** 스위치.
   - 고급: 시작/끝 초 **구간 트림**, dedup **임계값**(0.80~1.00, 높을수록 더 비슷해야 스킵).
   - 추출은 백그라운드로 돌아 우상단 진행 패널로 넘어가므로, 진행 중에 다른 화면으로 이동해도 됩니다.
   - **끝나면 영상은 지웁니다.** 프레임을 얻는 수단일 뿐이라 보관하지 않습니다.
   - 프레임은 **원본 그대로** 저장됩니다(타일로 쪼개지 않습니다). 작은 객체는 오토라벨링의 **Tiled** 추론이 맡습니다.
   - 파일명은 `{영상이름}_00001.jpg` 이고 번호는 **저장 순서**입니다(원본 프레임 번호가 아닙니다). 영상 이름은 한글·공백을 그대로 쓰고, URL 이나 윈도우에서 깨지는 문자(`# ? % : * " < > |`)만 `_` 로 바뀝니다.
   - **같은 이름이 이미 있으면 덮어쓰지 않고 `(2)` 로 갈라 넣습니다.** 이름이 같아도 다른 영상일 수 있으니까요. 같은 영상을 fps만 바꿔 다시 뽑아도 `경기 영상 (2)_00001…` 로 따로 쌓여 두 추출이 섞이지 않습니다. 실수로 같은 것을 두 번 넣었다면 이름 검색에 `(2)` 를 넣고 `Select all` → `Delete` 로 지우면 됩니다.
2. **기존 데이터셋(YOLO zip)** — 이미지+labels+data.yaml 을 라벨째 가져옵니다. 클래스는 이 데이터셋의 `classes.json` 에 병합되고 라벨의 클래스 id는 자동 리맵됩니다.
   - **"이미 검증이 끝난 데이터입니다"**(기본 켜짐) — 켜면 **검수완료**로 들어오고, zip 의 `train/val/test`(`valid` 도 인식) 폴더가 그대로 분할 배정이 됩니다. 폴더가 없으면 검수완료·미할당으로 둡니다.
   - 끄면 폴더 구조를 **읽지 않고** 전부 미검수로 들어옵니다 — 검증되지 않은 데이터의 분할을 믿을 근거가 없기 때문입니다.

**Sources**(제목 옆 버튼, 모달) — **이 데이터가 어디서 왔는지**의 목록입니다. 영상은 프레임을 뽑고 버리기 때문에 여기가 유일한 기록입니다.

- 파일명 · 언제 · 상태, 영상이면 **몇 프레임**과 fps·구간 설정, zip이면 이미지/라벨 수와 검증 여부.
- 프레임 이름 앞부분(`경기 영상 (2)_00001 …`)이 함께 보여서, **같은 영상이 두 번 들어갔을 때 어느 쪽이 `(2)` 인지** 한눈에 확인됩니다. 그 문자열을 이름 검색에 넣으면 그 출처의 이미지만 골라집니다.

**탭 — 미검수 / 검수완료**
- **미검수**: 썸네일 그리드 + `Import images`. 이미지를 눌러 라벨 에디터로 들어가고, 거기서 검수 완료로 표시하면 검수완료 탭으로 넘어갑니다.
- **검수완료**: 하위 필터 `전체 / 미할당 / train / val / test`, **Split**·**Export**(모두 모달).

**그리드 공통**
- 썸네일 위에 라벨 박스가 오버레이로 그려집니다.
- **선택**: 체크박스, **Shift-클릭 범위선택**, **Ctrl/⌘-클릭 토글**, 배경 **드래그 러버밴드 선택**.
- **하단 작업 바**: `Select all` 은 보이는 페이지가 아니라 **지금 필터에 걸린 전부**를 고릅니다(검수 여부 + split + 검색어 기준). 페이지가 60장 단위라, 수천 장을 넘길 때 이게 없으면 페이지를 돌며 손으로 골라야 합니다.
- 바의 일괄 작업: **오토라벨링**(미검수 탭, **고른 것에만**) / **검수 되돌리기**(검수완료 탭) / **삭제**.
- **오토라벨링의 추론 방식**: 모델을 여러 개 쌓을 수 있고 **모델마다** 방식을 고릅니다.
  - **Full scan** — 원본을 `Image size` 로 맞춰 한 번 추론. 큰 객체에 맞고 빠릅니다.
  - **Tiled** — 격자로 잘라 각각 추론한 뒤 원본 좌표로 되돌려 합칩니다. **작은 객체**(공)에 맞고, 추론이 타일 수만큼 늘어납니다.
  - `Image size` 는 **두 방식 모두** 씁니다. 타일보다 크게 잡으면 확대되어 작은 객체가 살아납니다(640 타일을 1280 으로 보면 2배).
  - `Stride` 의 겹침은 **가장 큰 객체보다 커야** 합니다. `Border margin` 은 타일 경계에 닿은 검출을 버리는 폭으로, 잘린 박스 대신 옆 타일이 온전히 본 것을 씁니다.
  - 라벨은 어느 방식이든 **원본 좌표**로 저장됩니다 — 검수 화면은 달라지지 않습니다.
- **일괄 "검수 완료"는 없습니다.** 검수는 한 장씩 봐야 의미가 있어서 라벨 에디터에서만 합니다. 되돌리는 쪽만 일괄로 둡니다.
- **필터**: 이름 검색 · 클래스별(**No class (negative)** 포함) · 정렬(생성일·이름). 검수완료 탭에는 `전체 / 미할당 / train / val / test` 가 더 있습니다.
- **배지**: 파란 **L**(박스 있는 라벨) · 회색 **N**(빈 라벨 = 네거티브) · **train/val/test**(어느 split 인지). 검수 여부 배지는 없습니다 — 탭이 이미 그것으로 갈라져 있습니다.

### 라벨 에디터 (Label Editor)
단일 이미지의 박스를 그리고 편집하는 화면. Konva 캔버스 기반.
- **캔버스**: 휠 확대, 드래그 이동(이미지가 항상 화면을 채우도록 클램프). **Select**(선택·이동·핸들 리사이즈)와 **Draw**(드래그로 새 박스) 두 도구. 검수 필요(needs_review) 자동 라벨은 점선으로 표시.
- **상단바**: 데이터셋으로 돌아가기, 저장 상태 배지(편집 2초 후 & 이동 시 자동 저장), 이전/다음 화살표와 "N / 전체" 위치, **검수 완료 토글**, 이미지 삭제.
- **우측 패널**: 모든 박스 목록(클래스 색·이름·신뢰도%), 클릭 시 캔버스에서 선택.
- **키보드 단축키**: `←/→` 이전·다음 · `V` 선택 · `W` 그리기 · `D`/Delete/Backspace 박스삭제 · `1~9` 클래스 지정 · `R` 검수토글 · `⌘/Ctrl+C·V` 박스 복사/붙여넣기 · `⌘/Ctrl+Z / Shift+Z` 실행취소/재실행 · `Esc` 선택해제. *(한글 IME 상태에서도 동작하도록 물리 키 기준으로 매칭)*

### 클래스 관리
클래스는 **그 데이터셋 것**입니다. 같은 이미지를 다른 데이터셋에 넣었더라도 거기서 보는 목록은
그쪽 것입니다. 데이터셋 화면 오른쪽 위 **Classes** 버튼으로 엽니다(미검수·검수완료 어느 탭에서든).
- 클래스 추가 · 이름변경 · 삭제. 각 행에 **id · 색상칩 · 이름 · 박스 수** 표시.
- 삭제는 되돌릴 수 없어서, 누르기 전에 **몇 개의 박스가 사라지고 뒤 클래스가 몇 번이 되는지**를
  먼저 보여 줍니다. 클래스 id는 라벨 파일이 위치로 참조하므로 빈자리 없이 앞당겨집니다.
- 라벨 에디터에서는 작업 중 **새 클래스를 추가**할 수 있습니다. 이름변경·삭제는 여기서만 합니다 —
  라벨을 그리는 도중에 번호가 밀리면 편집 중인 박스가 다른 클래스가 되어 버리기 때문입니다.
- 오토라벨링·데이터셋 가져오기 시 새 클래스가 자동으로 추가되기도 합니다.

### 오토라벨링 (Auto Labeling)
선택 이미지(또는 전체)에 모델 1~N개를 돌려 박스를 자동 생성합니다.
- **모델 다중선택**(서로 다른 모델의 클래스는 **이름 기준으로 union**), **신뢰도 임계값**(이 값 미만 박스는 버림 — 융합 결과에 대한 하드 필터).
- 고급: **WBF IoU**(서로 다른 모델 박스를 병합하는 기준), **이미지 크기**, **클래스별 최대 박스 수**(예: 공=1 처럼 클래스마다 상위 N개만 남김. 기본 300=무제한).
- 여러 모델이 공유하는 클래스는 **Weighted Box Fusion**으로 병합됩니다. 자동 라벨은 항상 "검수 필요" 상태이며, 재라벨링 시 해당 이미지의 검수 완료 플래그는 리셋됩니다.
- 학습이 도는 중이면 GPU 경합 경고가 뜹니다(같은 GPU를 두 작업이 나눠 쓰게 됨).

### 나누기 (Split)
검수완료 이미지를 train / val / test 로 나눕니다. 기본 비율은 **8 : 1 : 1**.

- 기본은 **미할당만** 배정합니다. 이미 train/val/test 에 들어간 이미지는 건드리지 않습니다 —
  안 그러면 test 가 학습에 새어 들어가 **이전 학습과 성능 비교가 불가능해집니다.**
- 전부 다시 섞으려면 **전체 다시 나누기**를 따로 눌러야 하고, 그때 경고가 뜹니다.
- 이미지를 더 넣고 다시 나눠도 기존 배정은 그대로 남습니다.

### 내보내기 (Export)
세 가지 zip 을 만듭니다. **검수완료가 아닌 이미지는 절대 나가지 않습니다.**

| 항목 | 담는 것 |
|---|---|
| **학습 데이터** | `train` + `val` (`data.yaml` 포함) |
| **테스트 데이터** | `test` |
| **원본 데이터** | 분할 무관, 검수완료 전부 |

- 이미지는 **하드링크**로 펼치므로 몇 번을 내보내도 디스크는 한 벌이고, 실제 용량이 드는 것은 zip 을 만들 때뿐입니다.
- **이력을 남기지 않습니다** — 만들어서 받으면 끝이고, 필요하면 언제든 다시 만듭니다.

### 학습 (Train)
Training 에 들어가면 **지난 학습 목록이 먼저** 보이고, `새 학습 시작` 을 누르면 시작 화면입니다.

1. **데이터셋 선택**: 드롭다운에 그 프로젝트의 데이터셋이 train/val 수와 함께 뜹니다(train 이 없는 데이터셋은 나오지 않습니다). **내보내기를 먼저 할 필요가 없습니다** — 학습이 데이터셋을 직접 먹고, test 는 빠집니다.
2. **베이스 모델 선택**: 레지스트리에서 시작 모델 선택.
3. **학습 설정**: 런 이름, 에폭, 이미지 크기, 배치, **디바이스**(auto/cpu/mps/0).
   - 고급: Patience, 초기 LR(lr0), 옵티마이저(SGD/Adam/AdamW/RMSProp), **증강 그리드**(좌우/상하 반전, 회전, 스케일, Mosaic, Mixup — Ultralytics 기본값 프리필).
4. **타일링**(옵션): 켜면 이번 학습의 train/val 만 타일로 잘라 먹입니다 — 데이터셋 자체는
   그대로 남고, 잘린 타일은 학습이 끝나면(성공이든 실패든) 자동으로 지워집니다. 타일
   크기·겹침·최소 가시비율을 조절할 수 있고, 네거티브(객체 없는 타일) 비율도 정할 수
   있습니다(`Estimate` 로 분할별 예상 장수 미리 확인). **test 는 손대지 않습니다** — 잘린
   타일은 이번 학습만의 것이고, 데이터셋에는 원본 프레임만 남습니다. 학습이 끝난 모델을
   **Benchmark** 에서 실제 배포 방식(타일 추론이든 풀 프레임이든)대로 평가하는 것은 그
   다음 이야기입니다.
- **한 번에 하나의 학습만** 실행됩니다(동시 실행 시 GPU 경합 경고).

### 학습 이력 & 상세 (Training History / Detail)
- **이력**: 프로젝트의 모든 학습 런 목록(이름·베이스모델·설정·mAP50·시작시각·상태). 진행 중 런은 스피너. 종료된 런만 삭제 가능(진행 중엔 먼저 중지).
- **상세 (실시간 모니터링)**:
  - 진행 중: "Epoch X / Y", 준비/최종검증(Finalizing) 상태, 경과 시간, **Stop** 버튼.
  - **Hero 지표**: mAP50 / mAP50-95 / Precision / Recall (큰 숫자=best.pt, 작은 숫자=last.pt).
  - **차트**: mAP·P/R 라인차트(best epoch 기준선), 상세 그래프(train/val loss, LR), 클래스별 지표(에폭 추이 라인차트 + 정렬 가능한 표).
  - **결과 이미지**: 학습 곡선·혼동행렬·PR/P/R/F1 커브·라벨 분포·예측 샘플(라이트박스).
  - **학습 로그**: 원본 stdout/stderr(마지막 256KB), 에러 시 자동 펼침.
  - **가중치 다운로드**(best.pt/last.pt) 및 **Add to Models**(레지스트리에 등록 → 재라벨링 루프로).

### 모델 레지스트리 (Models)
- **모델 추가**: **공식 모델 다운로드**(yolo26/12/11 × n~x 카탈로그, 클수록 정확하지만 느림) 또는 **`.pt` 업로드**(로드해서 클래스명·태스크 검증).
- **표**: 이름 · 출처 배지(Official/Uploaded/Trained) · 클래스 수 · 등록일. 행 메뉴에서 `.pt` 다운로드·이름변경·삭제.

### 연구실 (Lab)
연구실은 **하나**입니다(`basketball-adaptive-crop`). 라벨도 클래스도 쓰지 않고 **영상과 크롭 런만** 갖습니다. 모델은 공유 풀과 모든 학습실 프로젝트에서 **전부** 고를 수 있습니다.

`/lab` 에 들어가면 목록에 그 연구실이 무슨 연구인지가 적혀 있고, 누르면 안으로 들어갑니다. 사이드바는 **Crop** · **Crop Runs** 둘뿐입니다.

- **만들거나 지울 수 없습니다.** 새 연구실은 코드로 들어옵니다 — 이름과 설명도 코드가 갖습니다.
- **영상 탭이 따로 없습니다.** 크롭할 원본은 Crop 화면의 영상 고르는 자리에서 바로 올리고 지웁니다(학습실 Train 화면의 데이터셋과 같은 형태). 학습실 업로드와 달리 **프레임을 추출하지 않습니다** — 학습 재료가 아니라 크롭해서 내보낼 대상이니까요.
- **설정 화면도 없습니다.** 새 런은 **가장 최근 런의 설정**에서 출발합니다. 따로 저장해 둘 기본값이 없으니 저장 버튼도 없고, 마지막에 쓴 설정이 자연히 따라옵니다. 지난 런의 기록은 그대로입니다(런마다 그때 쓴 값이 박힙니다).

### Crop — 런처 하나
한 화면에서 전부 정하고 시작합니다. 시작하면 곧장 **상세 페이지로 넘어가고** 진행률은 거기서 봅니다(학습과 같습니다).

| 섹션 | 정하는 것 |
|---|---|
| 테스트 이름 | 런 이름 (비우면 영상 이름) |
| 영상 | 연구실 아카이브에서 선택 |
| 모델 세팅 | 모델 여러 개 + 각각 추론 방식(Full scan / Tiled) |
| 크롭 세팅 | 튜닝 노브 + **크롭 크기(px)** — 기본 608×1080 |
| 출력 세팅 | 그리기 도구 개별 토글 — 추론 박스 · 선수 궤적 · 공 궤적 · 타깃 · 크롭 박스 · 데드존 · 중앙선 |

크기는 **비율이 아니라 절대 px** 입니다. 608×1080 은 1080p 소스에서 9:16 과 같은 창이고, 높이를 소스보다 낮게 잡으면 **위아래도 실제로 잘립니다**(가운데를 남깁니다). 소스보다 큰 값은 소스 크기로 줄여 맞추고, 시작 전에 실제로 나올 크기를 알려 줍니다.

좌표 계산은 [adaptive-crop](https://github.com/Jh0-0y/adaptive-crop) 패키지가 하며, `ball` 클래스가 있는 모델(스포츠 영상)이 필요합니다.

**산출물은 항상 셋입니다.** 선택이 아닙니다.

- `crop.json` — 좌표
- `wide.mp4` — 가로 영상. 그리기 옵션이 있으면 오버레이를 구운 렌더본, 하나도 없으면 원본 그대로
- `crop.mp4` — 세로 크롭 영상 (오버레이 없는 깨끗한 산출물)

가로 영상은 **원본과 완전히 분리**됩니다 — 아카이브에서 영상을 지워도 런은 온전합니다. 그릴 것이 없을 때는 하드링크로 만들기 때문에 디스크는 한 벌만 씁니다(같은 볼륨이 아니면 복사로 떨어집니다).

조준선은 **타깃 종류에 따라 색이 다릅니다** — 공(빨강) · 공+선수(초록) · 선수 군집(파랑) · 중앙 폴백(회색). 신뢰도는 색의 농도로 나타납니다. 색이 바뀌는 구간이 곧 공과 선수의 비중이 뒤집힌 구간입니다.

### Crop Runs — 크롭 실행 이력
시작한 런이 **성공·실패 가리지 않고** 전부 남습니다. 상태로 거를 수 있고, 도는 게 있으면 3초마다 갱신됩니다.

- **만료가 없습니다.** 지우는 것은 사용자뿐입니다.
- 행을 누르면 상세 — 위에는 설정 표(쓴 모델·추론 방식·노브·크롭 크기·출력 옵션·커버리지), 아래에는 **가로와 세로 영상이 나란히** 재생되고, 그 아래에서 셋을 내려받습니다.
- **런 복제**: "이 설정 그대로 다시, 모델만 바꿔서" — 모델 업그레이드 전후를 즉시 비교합니다.
- 상태는 저장되지 않고 서버가 진행률 파일에서 그때그때 만듭니다 — 그래서 다른 브라우저나 다른 기기에서 열어도 같은 현황이 보입니다.

### 벤치마크 (Models 페이지 · Benchmark 탭)
**New benchmark** → 데이터셋 고르기 → 겨룰 모델을 줄줄이 추가하고 **모델마다 Full scan / Tiled**(와 타일 노브) 지정 → 신뢰도·매칭 IoU → 실행.

- **정답은 그 데이터셋의 `test` 분할입니다.** 따로 zip 을 만들어 올리지 않습니다 — "이 점수가 어느 데이터에서 나온 건가"에 언제든 답할 수 있습니다.
- **신뢰도는 벤치마크 전체에 하나뿐입니다.** 모델마다 다르면 동작점이 달라 P/R 을 나란히 놓을 수 없기 때문입니다. 대신 **추론 방식은 모델마다** 다르게 둡니다 — 타일 모델과 풀 프레임 모델이 각자 배포될 방식대로 같은 정답 위에서 겨룹니다.
- **Tiled 엔트리는 test 프레임을 실제로 자릅니다** — 다만 자르는 시점이 추론이라, 타일은 파일로 남지 않습니다. 타일마다 모델을 돌린 뒤 검출을 원본 프레임 좌표로 되돌리고 겹친 것을 합쳐 놓습니다. 학습의 타일링(파일로 잘라 두고 그 파일로 학습)과 갈리는 지점이 여기이고, 어느 쪽이든 데이터셋에 저장되는 것은 원본 프레임뿐입니다.
- **표의 한 줄은 모델이 아니라 "이 설정으로 돌린 그 모델"입니다.** 점수는 test 이미지 **한 장 단위**로 매겨지므로, Tiled 로 돌린 줄의 P/R/F1 도 타일당이 아니라 *사진 한 장에서 무엇을 맞히고 무엇을 놓쳤나*입니다. `Merge IoU` · `Border margin` 처럼 타일을 합칠 때 쓰는 값도 점수에 그대로 반영됩니다 — 그래서 같은 모델을 방식이나 노브만 바꿔 두 줄로 넣고 어느 쪽이 나은지 볼 수 있고, 이긴 줄은 **"그 설정 그대로 배포하면 이 성적이 나온다"**로 읽으면 됩니다.
- **결과 화면은 TensorBoard 같은 모양입니다.** 왼쪽 레일에 겨루는 엔트리들이 색깔 있는 계열로 나열되고 켜고 끌 수 있으며, 그 아래 **신뢰도 슬라이더**가 있습니다. 화면을 열면 슬라이더는 자동으로 **그 벤치마크를 실행할 때 정한 신뢰도**에 맞춰집니다 — 그 값이 이 벤치마크의 기준점이고, 슬라이더는 그 앞뒤를 둘러보는 도구입니다.
- 오른쪽은 네 탭입니다. **Scalars**는 엔트리별 mAP50·mAP50-95·AP75·P/R/F1·TP/FP/FN·추론 속도(ms/img)·파라미터 수를 한 표로("Best mAP" 배지 포함), 크기별 AP와 속도를 막대차트로, 클래스별 표를 함께 보여줍니다. **Curves**는 신뢰도를 옮겨가며 정밀도·재현율·F1이 어떻게 바뀌는지 보여주는데, 이 곡선은 **항상 IoU 0.50 기준**이라 카드 제목에 그 값이 박혀 있습니다 — 벤치마크를 IoU 0.7 같은 값으로 돌렸다면 슬라이더 옆 헤드라인 숫자와 곡선이 다르게 보이는 게 정상입니다. **Matrix**는 혼동행렬(행=실제, 열=예측, 양 끝에 놓친 것·헛것을 모으는 background 칸)을, **Images**는 이미지별 박스 오버레이(GT=녹색 점선, 엔트리별 색상 실선)를 보여줍니다.
- **크기별 AP**가 타일링 판단의 핵심입니다 — 작은 객체(넓이 32×32=1,024px² 미만)에서 AP가 낮다면 타일링이 필요하다는 신호이고, 타일링을 켠 엔트리에서 그 숫자가 실제로 올라갔는지가 "타일링이 정말 도움이 됐는가"의 답입니다.
- 이 지표들은 전부 최근에 추가된 것이라 **예전에 실행한 벤치마크에는 없을 수 있습니다.** 그런 런을 열어도 화면이 빈 차트를 그리지는 않습니다 — 데이터가 없는 탭(Curves·Matrix)을 아예 숨깁니다.
- **이력이 남습니다.** 실행한 벤치마크는 표에 쌓이고 눌러서 언제든 다시 엽니다. 채점에 쓴 이미지도 런과 함께 남아 오버레이가 나중에도 그대로 보입니다. **만료가 없고** 지우는 것은 사용자뿐입니다.
- 진행 현황과 상태는 **크롭 런과 똑같이** 다룹니다.

### 전역 작업 인디케이터
영상 가져오기·오토라벨링 진행률을 우상단 패널 하나로 통합 표시합니다. 단계별 진행바, **실행 중 작업 취소**, 완료 시 토스트·데이터 새로고침, 새로고침 후 재연결(SSE).

- **크롭 런·학습·벤치마크는 여기 오지 않습니다.** 각자 상세 페이지가 진행률을 보여줍니다 — 결과를 볼 자리가 이미 있으니까요.
- 페이지 이탈 방지는 **브라우저가 파일을 올리는 중**일 때만 겁니다. 서버에서 도는 작업은 새로고침해도 다시 붙으므로 막지 않습니다.

## 5. 실행 방법

> **환경 요약**
> - **운영(GPU 학습 포함)은 윈도우 + NVIDIA GPU PC에서 Docker로.** Docker 구성은 GPU를 무조건 요구하므로 GPU 없는 호스트에선 컨테이너가 뜨지 않습니다(의도된 설계).
> - **맥은 로컬 개발 실행(`dev.sh`) 전용입니다.** 맥에는 NVIDIA GPU가 없어 Docker 배포 구성을 쓸 수 없고, 대신 로컬에서 직접 띄워 씁니다(가속은 Apple **MPS**, 없으면 CPU 자동 선택). 즉 맥은 "내 PC에서만" 돌리는 개발/시험 용도입니다.
> - 가속기 선택은 자동: 맥=MPS, 윈도우/리눅스=CUDA, 없으면 CPU.

### 5-1. 윈도우 GPU PC 배포 (Docker) — 권장 운영 방식

**빌드·푸시는 내 PC에서, 실행은 서버에서** — 역할이 나뉩니다. `docker-compose.yml`은 **GHCR 이미지를 pull 해서 실행하는 배포 전용**(compose에 `build:` 없음)이고, 이미지를 굽고 올리는 건 `scripts/build.sh`가 담당합니다. 외부에는 프론트 포트 **하나(3000)** 만 열면 됩니다 — nginx가 `/api`를 백엔드(내부 8000)로 프록시합니다.

#### 사전 준비 (서버, 1회)
1. **Docker Desktop** 설치 → Settings에서 **WSL2 기반 엔진** 활성화.
2. 최신 **NVIDIA 드라이버** 설치. *(백엔드 이미지는 CUDA 12.6 런타임 기준입니다. CUDA 12.x는 마이너 버전 호환이라 12.x를 지원하는 드라이버면 대체로 동작하지만, 드라이버가 오래됐다면 갱신하세요.)*
3. GPU 인식 확인:
   ```bash
   docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
   ```

배포는 **① 내 PC에서 이미지로 만들어 GitHub(GHCR)에 올리기 → ② 서버에서 그 이미지를 받아 실행하기** 두 단계로 나뉩니다.

#### ① 이미지 빌드 & GitHub(GHCR) 업로드 — 내 PC(맥 포함)에서

소스를 이미지로 굽고 GitHub Container Registry(GHCR)에 올립니다. `scripts/build.sh`가 backend·frontend 두 이미지를 빌드해서 바로 push까지 합니다.

> ⚠️ **이미지는 어디서 빌드하든 항상 윈도우(`linux/amd64`) 기준으로 만들어져야 합니다.** 빌드하는 컴퓨터는 맥일 수도, 윈도우일 수도 있지만 **실행 대상은 언제나 윈도우 GPU PC**이기 때문입니다. `build.sh`는 이 플랫폼을 `linux/amd64`로 **하드코딩**해 어떤 호스트에서 돌려도 항상 윈도우용 이미지가 나오도록 강제합니다 — 그래서 맥(arm64)에서 빌드해도 안전합니다. (직접 `docker build`로 굽지 말고 반드시 `build.sh`를 쓰세요. 맨 아래 수동 방법을 쓰더라도 `--platform linux/amd64`를 반드시 붙여야 합니다.)

> ⚠️ **백엔드 이미지 빌드에는 GitHub 토큰이 필요합니다.** 크롭 좌표 계산에 쓰는 [adaptive-crop](https://github.com/Jh0-0y/adaptive-crop)이 비공개 저장소라, 빌드 중 pip이 그걸 받아와야 합니다. 토큰은 `--secret`으로 넘깁니다 — **설치 URL에 박으면 안 됩니다**(pip이 `.dist-info/direct_url.json`에 URL을 그대로 기록해서 이미지에 토큰이 남습니다). 필요한 권한은 그 저장소에 대한 읽기(fine-grained PAT의 Contents: Read)뿐입니다.

```bash
# 1) GHCR 로그인 (최초 1회) — PAT 는 write:packages 권한 필요
echo <GITHUB_TOKEN> | docker login ghcr.io -u jh0-0y --password-stdin

# 2) 빌드 + 푸시 (한 방에) — 호스트가 맥이든 윈도우든 결과는 항상 linux/amd64 이미지
#    GH_PAT: adaptive-crop 저장소 읽기 권한이 있는 토큰
GH_PAT=<GITHUB_TOKEN> TAG=v1.2.3 scripts/build.sh   # 버전 태그 지정 (생략 시 latest)
```
- 플랫폼은 `build.sh` 안에서 `--platform linux/amd64`로 **고정**됩니다 — 맥(arm64)에서 빌드해도 윈도우용 이미지가 나옵니다. *(맥 등 non-amd64 호스트의 첫 빌드는 에뮬레이션이라 다소 느림)*
- 만들어지는 이미지: `ghcr.io/jh0-0y/yvt-backend:${TAG}` 와 `ghcr.io/jh0-0y/yvt-frontend:${TAG}`.
- 완료되면 GitHub 저장소의 **Packages** 에서 올라간 이미지를 확인할 수 있습니다.
- **패키지 공개 설정(최초 1회)**: GHCR 패키지는 처음엔 비공개(private)로 생성됩니다. 이 프로젝트는 **공개(public)로 운영**하므로, 각 패키지(yvt-backend, yvt-frontend)의 GitHub *Package settings → Change visibility → Public* 에서 한 번 공개로 바꿔두면 됩니다. 공개로 두면 **서버에서 `docker login` 없이 바로 pull** 할 수 있습니다.

<details>
<summary>build.sh 없이 수동으로 빌드·푸시하려면 (⚠️ --platform 필수)</summary>

`--platform linux/amd64`를 빠뜨리면 맥에서는 arm64 이미지가 나와 윈도우 서버에서 실행되지 않습니다. 백엔드는 `--secret id=gh_pat`도 빠뜨리면 안 됩니다(비공개 adaptive-crop 설치 실패).

```bash
GH_PAT=<GITHUB_TOKEN> docker buildx build --platform linux/amd64 --secret id=gh_pat,env=GH_PAT \
  -f docker/backend.Dockerfile  -t ghcr.io/jh0-0y/yvt-backend:v1.2.3  --push .
docker buildx build --platform linux/amd64 \
  -f docker/frontend.Dockerfile -t ghcr.io/jh0-0y/yvt-frontend:v1.2.3 --push .
```
</details>

#### ② 배포 환경에서 그 이미지로 실행 — 서버(윈도우 GPU PC)에서

서버에는 **소스가 필요 없습니다.** `docker-compose.yml` 과 `.env` 두 파일만 있으면 GHCR에서 이미지를 받아 실행합니다(compose에 `build:`가 없는 배포 전용 구성). 이미지가 **공개(public)** 라서 **로그인도 필요 없습니다.**

```bash
# 1) 실행에 필요한 두 파일만 서버에 둔다: docker-compose.yml, example.env
cp example.env .env   # DATA_DIR·CACHE_DIR 경로 + TAG(실행할 버전) 를 환경에 맞게 수정

# 2) 이미지 받아서 실행 (공개 이미지라 docker login 불필요)
docker compose up -d   # pull_policy: always 라 .env 의 TAG 에 맞는 최신 이미지를 받아 뜬다
```
- **어떤 버전이 뜨는지는 `.env`의 `TAG`가 결정합니다** — ①에서 푸시한 태그(예: `v1.2.3`)를 여기에 적으면 그 버전이 실행됩니다.
- 업데이트 배포: 새 버전을 ①로 다시 푸시 → 서버 `.env`의 `TAG`를 새 값으로 바꾸고 `docker compose up -d` 재실행.
- 로그 확인: `docker compose logs -f` · 중지: `docker compose down`.

#### 접속
- **로컬**: `http://localhost:3000`
- **외부**: 공유기 포트포워딩(외부포트 → PC:3000) + 윈도우 방화벽 **3000 인바운드 허용**. (백엔드 8000은 호스트 내부 전용이라 열 필요 없음)

#### 저장 경로 (`.env`)
| 변수 | 용도 |
|---|---|
| `DATA_DIR` | **영구 저장소(HDD 권장)** — 데이터셋·모델·학습결과·DB. **백업은 이 폴더만** 하면 됩니다. |
| `CACHE_DIR` | **학습용 SSD 캐시** — 학습 시작 시 데이터셋을 여기로 복사해 돌리고, 끝나면(성공/실패/취소 무관) 자동 삭제. 스테이징이 불필요하면 `DATA_DIR`과 같은 경로로 두면 복사를 건너뜁니다. |

#### 보안 주의
> ⚠️ **현재 로그인/인증 기능이 없습니다.** 인터넷에 직접 노출하면 누구나 데이터·모델에 접근하고 학습을 실행할 수 있습니다. 가급적 **VPN(Tailscale 등)이나 신뢰할 수 있는 네트워크 안에서만** 열어두세요.

### 5-2. 로컬 개발 실행 (맥 / CPU)

```bash
# 최초 1회 — 의존성 설치 (Python 3.12 + uv, Node)
cd backend && uv sync && cd ../frontend && npm install && cd ..

# 백엔드 + 프론트 동시 실행 (Ctrl+C 한 번으로 둘 다 종료)
./dev.sh

  --conf 0.4
```

옵션: `--iou-wbf 0.55` · `--device auto|cpu|mps|0` · `--imgsz 640` · `--batch 16`

- 모델별 클래스가 달라도 클래스명 기준으로 union됩니다 (A={person,car}, B={car,dog} → {person,car,dog}).
- 복수 모델이 공유하는 클래스는 Weighted Box Fusion으로 병합됩니다.
- 출력: `output/labels/*.txt`(이미지별 YOLO 라벨, 빈 파일=네거티브), `output/classes.json`(글로벌 클래스 레지스트리).

## 7. 기술 스택 & 아키텍처

**프론트엔드**: React 19 · TypeScript · Vite · Mantine(UI) · TanStack Query · Zustand · React Router · Konva(라벨 캔버스) · Recharts(차트).

**백엔드**: Python 3.12 · FastAPI · SQLModel(SQLite) · Ultralytics(YOLO) · PyTorch · SSE(진행 스트리밍) · uv(패키지) · [adaptive-crop](https://github.com/Jh0-0y/adaptive-crop)(세로 크롭 좌표 계산).

**크롭 파이프라인은 외부 라이브러리다.** 공·선수를 추적해 세로 크롭 X 좌표를 내는 계산은 이 저장소에 없고 `adaptive-crop` 패키지가 한다 — 운영 CropWorker와 **같은 코드로 같은 좌표**를 내야 여기서 맞춘 튜닝을 믿을 수 있기 때문이다. 툴킷이 갖는 것은 그 좌표를 프레임에 그리고 잘라 내는 부분(`lib/crop/`)과, 둘을 잇는 얇은 어댑터(`lib/crop/plan.py`)뿐이다.

**계층 경계 (백엔드 대원칙)**:
> **API·services = 비즈니스·상태·결정·DB / workers = 순수 계산(별도 프로세스, torch·CUDA는 여기서만) / ml·domain = 순수 함수(프로세스·DB 모름).**

- `app/` 밖에 두 패키지가 더 있다: `lib/`(순수 기능 — 영상 프로브·인코딩 등, 잡·DB·HTTP를 모른다)와 `infra/`(잡 배관 — `progress.jsonl`·`CANCEL`). 둘 다 `app/`을 import하지 않아 웹 없이도 쓸 수 있다.
- `torch`/`ultralytics`/CUDA는 `workers/`·`lib/detect/`에서만, 그것도 함수 안 lazy import — API 프로세스가 CUDA를 로드하지 않도록.
- DB(SQLite)는 API 프로세스에서만 접근. 워커는 값을 받아 계산하고 값을 돌려줄 뿐.
- 장시간 작업은 **파일 기반 IPC**: 진행상황은 `progress.jsonl` tail을 SSE로 스트리밍, 취소는 `CANCEL` 센티넬 파일.
- 모든 HTTP 경로는 `/api/v1/...` (인프라 프로브 `GET /api/health`만 예외).

- 크롭 좌표 계산만 외부 패키지(`adaptive_crop`)에 있고, 워커·API는 그것을 부르기만 한다 — 계층 경계는 동일하게 적용된다(패키지 import도 워커/함수 안 lazy import).

## 8. 데이터 저장 구조

모든 영구 데이터는 `DATA_DIR` 아래에 저장됩니다(백업은 이 폴더 하나면 충분).

```
DATA_DIR/
├── db.sqlite3            # 프로젝트/연구실/모델/잡/학습런 메타 (SQLite)
├── models/               # 공유 모델 풀 (models/{id}/model.pt + meta.json)
├── projects/             # 학습실 — 프로젝트별 폴더
│   └── {project_id}/
│       ├── project.json
│       ├── models/       # 프로젝트 스코프 모델
│       ├── runs/         # 프로젝트 스코프 학습 결과
│       ├── benchmarks/   # 벤치마크 런 (run.json · result.json · images_manifest.json · dataset/)
│       └── datasets/     # 데이터셋 하나가 자기 것을 전부 갖는다
│           └── {dataset_id}/
│               ├── dataset.json   # 이름 · 생성일
│               ├── raw/           # 이미지
│               ├── thumbs/        # 썸네일(JPEG) — 요청할 때 만든다
│               ├── labels/        # 이미지별 YOLO 라벨 (.txt)
│               ├── classes.json   # 이 데이터셋만의 클래스
│               ├── reviewed.json  # 검수 완료 플래그
│               └── splits.json    # train / val / test 배정
├── labs/                 # 연구실 — 하나뿐이지만 자리는 id 별로 갈라 둔다
│   └── {lab_id}/
│       ├── lab.json      # 이름 표시 (진실은 코드 상수)
│       ├── videos/       # 크롭할 원본 + 사이드카 (프레임 추출 없음)
│       └── crops/        # 크롭 런 (run.json · crop.json · wide.mp4 · crop.mp4)
├── jobs/                 # 잡 진행/취소 (jobs/{id}/progress.jsonl · CANCEL)
└── test/                 # 단발 추론 업로드 임시물 (DB 미기록, 쓰고 바로 삭제)
```

- **데이터 모델**(SQLite 테이블): `Project`(학습실) · `LabProject`(연구실) · `ModelEntry`(모델 레지스트리) · `Job`(오토라벨링) · `TrainRun`(학습). 데이터셋·라벨·클래스·검수플래그·분할·연구실 영상·크롭 런 등은 DB가 아니라 폴더의 **파일**로 관리됩니다 — **디렉터리가 곧 목록**입니다.
- 데이터셋 수치(미검수·검수완료·train/val/test)는 저장하지 않고 서버가 **파일을 세어** 만듭니다. 저장한 값은 언젠가 실제와 어긋나고, 그 어긋남은 조용하기 때문입니다.
- 학습이 먹는 트리(`runs/{run_id}/dataset/`)와 내보내기 zip 의 이미지는 **하드링크**입니다 — 몇 번을 돌려도 이미지 바이트는 한 벌입니다.
- 크롭 런의 가로 영상은 그릴 것이 없으면 **원본 하드링크**입니다 — 런이 늘어도 디스크는 한 벌만 씁니다.
- 벤치마크 런은 채점에 쓴 `test` 이미지를 자기 폴더(`benchmarks/{id}/dataset/`)에 **하드링크로** 들고 있습니다. 그래서 과거 벤치마크를 다시 열어도 오버레이가 그대로 보이고, 디스크는 여전히 한 벌입니다.
- 연구실 행은 하나만 씁니다. **id 는 절대 바뀌지 않고**(영상·크롭 런이 그 아래 있습니다) **이름·설명은 코드가 정합니다**.
