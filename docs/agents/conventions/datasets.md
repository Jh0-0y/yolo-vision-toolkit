# 데이터셋 규약

> 데이터셋 하나가 자기 것을 전부 갖고, 수치는 저장하지 않는다. 학습실 코드를 만질 때 읽는다.

## 하나가 전부 갖는다

`projects/{pid}/datasets/{did}/` 아래에 이미지·라벨·클래스·검수·분할이 **모두** 있다
(자리는 [데이터 배치](../data-layout.md)). **데이터셋끼리는 아무것도 공유하지 않는다** —
같은 영상을 두 데이터셋에 쓰려면 두 번 추출하고, 삭제는 디렉터리 통째로다.

클래스도 데이터셋 것이다. 같은 이미지를 다른 데이터셋에 넣었더라도 거기서 보는 목록은
그쪽 `classes.json` 이다.

## 수치는 파생한다 — 저장하지 않는다

`services/datasets.py` 의 `counts()` 가 파일을 세어 그 자리에서 만든다. 저장하면 실제와
어긋나는 순간이 오고, 그 어긋남은 조용하다. **디렉터리가 곧 목록이다** — 데이터셋에 DB 행이
없다(`services/lab_crop_runs.py` 와 같은 규약).

## 흐름은 한 방향이다

```
가져오기 ─→ 미검수 ─(검수)→ 검수완료·미할당 ─(타일링)→ 새 데이터셋 ─(비율 split)→ train / val / test
                                    └────────────────(비율 split)→ train / val / test
```

- 영상에서 뽑은 프레임은 **전부 미검수**로 들어온다. 영상은 추출이 끝나면 서버가 지운다.
- YOLO zip 은 **"이미 검증된 데이터"로 표시했을 때만** 검수완료로 들어오고, 그때 zip 의
  `train/val/test` 폴더가 그대로 분할 배정이 된다(`import_yolo.split_of`). 표시하지 않으면
  폴더를 **읽지 않는다** — 검증되지 않은 데이터의 분할을 믿을 근거가 없다.
- **검수완료가 아닌 것은 절대 나가지 않는다** — 학습에도 내보내기에도.
- **일괄 "검수 완료"는 없다.** 검수는 한 장씩 봐야 의미가 있어 라벨 에디터에서만 한다.
  되돌리는 쪽만 일괄로 둔다 — 안전한 방향이다.
- **오토라벨링은 고른 것에만 돈다.** 대상을 비우면 422 다. 비우면 "데이터셋 전부"가 되어
  검수 끝난 라벨까지 모델 출력으로 덮어썼고, 그 이미지는 검수완료 딱지를 단 채 남았다.
- **영상 추출은 원본 프레임만 남긴다.** 타일로 쪼개면 검수할 장수가 타일 수만큼 늘고,
  타일은 다시 프레임으로 합칠 수 없어 전처리 결정이 데이터셋에 박제된다. 작은 객체를
  놓치는 문제는 **오토라벨링의 타일 추론**이 맡는다.
- **타일링은 분할 앞이고, 새 데이터셋을 만든다.** 검수완료 이미지를 타일로 쪼개
  `raw/`·`labels/`·`classes.json` 을 갖춘 **파생 데이터셋**을 낸다. 타일은 전부
  검수완료·미할당으로 나오고 분할은 거기서 따로 한다. 결과가 그냥 데이터셋이라
  내보내기·학습·라벨 에디터는 아무것도 바뀌지 않는다.
- **네거티브 비율은 포지티브 대비다.** `0.1` 이면 포지티브 100장에 네거티브 10장.
  "전부 담기"는 비율이 아니라 별도 스위치다 — 700장을 넣으려고 `7.0` 을 계산해서
  치게 하지 않는다. 고를 때는 **원본 라운드로빈**이다: 한 프레임에서 뭉텅이로 집으면
  배경이 한 장면에 쏠린다.
- **타일 크기는 세 곳에서 같아야 한다** — 데이터셋 타일 · 학습 `imgsz` · 그 모델로
  돌릴 타일 추론 `tile_size`. 그래서 타일링 설정을 파생 데이터셋의 `sources.json`
  에 박아 둔다.
- **중단된 타일링의 타일은 검수완료로 올리지 않는다.** 끝까지 간 것만 올린다 —
  반쪽 데이터셋이 검수완료 딱지를 달면 그대로 학습·내보내기로 새어 나간다.

## 추론 방식은 검출기 엔트리마다 고른다

오토라벨링은 `{모델 + 방식 + 노브}` 엔트리 목록을 받는다. 선수 모델은 풀 프레임으로
크게 보고 공 모델은 타일로 잘게 보는 식이 가능하다.

| 방식 | 하는 일 | 잘 맞는 것 |
|---|---|---|
| `full` | 원본을 `imgsz` 로 맞춰 한 번 추론 (ultralytics 가 좌표를 되돌린다) | 큰 객체, 빠름 |
| `tiled` | 격자로 잘라 배치 추론 → 원본 좌표 복원 → 경계 중복 병합 | **작은 객체**, 추론이 타일 수만큼 |

- **`imgsz` 는 두 방식 모두 쓴다.** 타일보다 크게 잡으면 확대되어 작은 객체가 살아난다
  (640 타일 안의 20px 공을 1280 으로 보면 40px). 타일 크기에 묶어 두면 확대할 수 없다.
- 병합이 **두 층**이다: 타일 경계 중복은 엔트리 안에서 `merge_iou` 로 NMS(좌표를 평균하지
  않는다 — 잘린 박스와 평균하면 둘 다보다 나빠진다), 그다음 모델 간 병합이 `iou_wbf` 로 WBF.
- `border_margin_px` 는 **타일 경계에 닿은 검출을 버리는 폭**이다. 타일 안에서는 잘린
  객체도 온전해 보여 구분할 수 없으므로, 겹침 구간에서 옆 타일이 온전히 본 것을 쓴다.
  그래서 겹침이 가장 큰 객체보다 커야 한다. 이미지 바깥 테두리는 예외다.
- **연구실의 `adaptive-crop` 을 쓰지 않는다.** 그쪽 타일 검출기는 검출을 `ball`·`player`
  라는 역할로 좁혀 돌려주어 학습실의 임의 클래스를 다룰 수 없고, 무엇보다 학습실은 어떤
  연구실 패키지도 몰라야 한다([아키텍처](../architecture.md)).

## 파일 이름은 한 곳에서 정한다

`lib/fsutil.py:safe_stem` 하나가 정한다 — 영상에서 뽑은 프레임도, zip 으로 들여온
이미지도 같은 규칙을 쓴다. 한쪽만 다르면 한쪽만 깨진다.

**막는 것은 깨지는 문자뿐이다.** 한글·공백·괄호는 그대로 둔다.

| 막는 것 | 왜 |
|---|---|
| `/` `\` | 경로 구분자 |
| `#` `?` `%` | 이미지 URL 이 깨진다 (프래그먼트·쿼리·잘못된 이스케이프) |
| `: * " < > \|` | 윈도우에서 불법 — 내보낸 zip 을 윈도우에서 못 푼다 |
| 제어문자 · 앞의 `.` | 앞의 점은 목록에서 빠지고 서빙도 막혀 **조용히 사라진다** |

NFC 로 정규화하고 150바이트에서 자른다. 영숫자만 남기던 옛 규칙은 **한글 이름을 통째로
지워** 이름이 다른 영상 둘이 같은 stem 을 갖고 서로 덮어썼다.

프레임 이름은 `{영상이름}_{00001}` 이고, 번호는 **저장 순서**다(원본 프레임 번호가
아니다). 타일링은 이 이름에 손대지 않는다 — 타일 stem 은 파생 데이터셋을 만들 때
`lib/media/tiling.py:tile_stem` 이 원본 stem 뒤에 `_r{row}c{col}` 을 붙여 새로 낸다.

zip 항목 이름은 **읽는 단계에서 한 번 더 고친다**(`import_yolo.zip_entry_name`).
zip 규격은 파일명을 CP437 로 쓰되 UTF-8 이면 플래그를 세우라고 하는데, macOS 가 만드는
zip 은 UTF-8 바이트를 넣고도 플래그를 세우지 않는다. 규격대로 읽으면 `스크린샷 …png` 이
`ßäëßà│…` 가 되어 그대로 데이터셋에 쌓인다. 그래서 `extractall` 대신 한 항목씩 풀고,
직접 푸는 만큼 **경로 탈출도 직접 막는다**.

**이름이 안전해도 URL 은 서버가 인코딩한다**(`dataset_images.py` 의 `quote`). zip 으로
들어온 이름까지 우리가 통제할 수는 없기 때문이다.

### 겹치면 덮어쓰지 않는다

이미 쓴 이름이면 `lib/fsutil.py:unique_stem` 이 ` (2)` · ` (3)` 을 붙인다. **이름이 같아도
다른 데이터일 수 있어서**, 무엇을 남길지는 사람이 보고 정한다. 덮어쓰면 그 판단을 기계가
조용히 내리고 사라진 쪽은 되돌릴 수 없다.

같은 것을 두 번 넣으면 두 벌이 된다 — 그건 이름으로 `(2)` 를 검색해 지울 수 있으므로
조용한 손실보다 낫다고 본다.

영상은 **프레임마다가 아니라 추출 단위로** 갈라진다(`경기 영상 (2)_00001`). 장마다 붙이면
번호와 접미사가 뒤엉켜 어느 추출에서 나왔는지 알 수 없다.

## 출처는 남긴다 — `sources.json`

영상은 프레임을 뽑고 **버리므로**, 남기지 않으면 `경기 영상 (2)` 를 보고도 그게 무슨
영상이었는지 알 길이 없다. zip 도 함께 기록한다 — "무슨 데이터를 썼나"는 영상만의 질문이
아니다.

- 기록은 **시작할 때** 쓴다. 이름은 그때 잡히므로, 추출이 죽어도 그 이름은 쓴 것으로 쳐야
  다음 추출이 덮어쓰지 않는다. 프레임 수는 끝나야 알기에 `on_done` 에서 채운다.
- **이름이 겹치는지도 이 기록으로 판단한다**(`used_stems`). 파일만 보면 프레임을 지운
  순간 "쓴 적 없는 이름"이 되어 다음 추출이 옛 이름을 다시 잡는다. 기록이 없던 시절
  데이터셋을 위해 파일도 함께 본다.
- **타일링 기록은 원본이 아니라 파생 데이터셋 쪽에 남는다.** 원본의 `frames` 수만으로는
  타일이 몇 장 나왔는지 알 수 없어, `source_dataset_id` 와 `tiles`/`positive`/`negative` 를
  파생 데이터셋의 `sources.json` 에 둔다.

## 분할은 기존 배정을 건드리지 않는다

`lib/labels/split.py:assign` 의 기본은 **미할당만** 배정한다. 이미 train/val/test 에 들어간
것을 다시 섞으면 test 가 학습에 새어 들어가 이전 평가와 비교가 안 된다.

전부 다시 섞는 것은 `reassign_all=True` 로 **명시할 때만** 하고, 화면은 그때 경고한다.

## 내보내기와 학습은 같은 함수를 쓴다

`lib/labels/dataset_export.py` 하나가 낸다. 담을 split 만 다르다.

| 종류 | 담는 것 |
|---|---|
| `train` | train + val — 학습에 바로 쓸 것 |
| `test` | test — 평가용 |
| `all` | 검수완료 전부, 분할 무관 |

- 이미지는 **하드링크**로 펼친다(`lib/fsutil.py:link_or_copy`). 몇 번을 내보내도 디스크는
  한 벌이고, 실제 바이트가 드는 것은 zip 을 만들 때뿐이다.
- 라벨은 링크하지 않고 **다시 쓴다** — 클래스를 걸러 id 를 0..n-1 로 다시 매기기 때문이다.
  박스가 안 남아도 빈 파일을 쓴다: 빈 라벨은 "안 그렸다"가 아니라 **"여기엔 없다"는 학습 신호**다.
- `materialize()` 는 트리까지, `build()` 는 이어서 zip 까지. **학습은 `materialize()` 를 쓴다** —
  내보내기를 먼저 할 필요가 없다.
- 내보내기는 **이력을 남기지 않는다.** 만들어서 받으면 끝이고, 목록이 필요하면 데이터셋이 목록이다.

## 학습 입력은 토큰 하나다

`dataset:{project_id}:{dataset_id}`. 다른 형태는 없다 — 옛 `export:` · `upload:` 는 사라졌다.
학습을 시작하면 그 데이터셋의 train/val 을 `runs/{run_id}/dataset/` 에 펼치고, 하드링크라
런을 지울 때 함께 사라진다.
