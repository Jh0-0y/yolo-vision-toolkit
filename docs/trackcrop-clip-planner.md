# Trackcrop 클립 플래너(2-패스) 설계

세로 숏폼용 크롭(1920×1080 → 608×1080 크롭 X 궤적) 파이프라인의 재설계 문서.
기존 브랜치들의 방식 비교와, 이를 대체하는 클립 플래너(2-패스) 설계를 기록한다.
클립 플래너는 파이프라인의 **유일한** 좌표 계산 경로다 (순차 방식은 제거됨).

## 1. 요구사항

입력: 약 20초 분량의 완성된 클립 영상 (라이브 아님 — **클립 전체를 한 번에 볼 수 있다**).
출력: 공 중심의 세로 크롭 X 궤적. 공을 놓치지 않으면서 크롭이 덜 흔들려야 한다.

제약·현실:

1. 공과 선수 객체 정보만 받을 수 있다.
2. 공은 작고 빨라서 프레임마다 탐지가 안 될 수 있다 (1920px 학습에도 불구).
3. 크롭은 공이 중심 — 드리블·슛·패스 등 농구 특성상 공의 움직임이 다양하다.
4. 오탐 외에 실제 공이 여러 개일 수 있다 (경기 공, 관중석/벤치의 공, 프린트 공).
5. 선수가 공을 들고 등을 돌리는 등 공이 장기간 안 보일 수 있다.
6. 카메라는 팬/줌이 있는 소스라 코트 영역(ROI) 사전 정의는 불가.

## 2. 기존 브랜치 방식 비교

계보: `72d19d2`(자체 ID 매칭 + 기본 채점)에서 `crop-deadzone`·`trackcrop-custom`이
분기, main은 ByteTrack 스펙 준수로 전환하며 데드존·게이팅·튜닝 config를 흡수,
`trackcrop-hybrid`는 main 위의 절충안.

| | crop-deadzone | trackcrop-custom | main | trackcrop-hybrid | **클립 2-패스** |
|---|---|---|---|---|---|
| 처리 구조 | 순차 (앞→뒤) | 순차 | 순차 | 순차 | **전역 (클립 전체)** |
| 판단 단위 | 프레임 | 프레임 | 프레임 | 프레임(+1s 윈도우) | **트랙(궤적)** |
| 결정 번복 | 불가 | 불가 | 불가 | 불가 | **가능** |
| 탐지·ID | predict+자체 매칭 | 동일 | ByteTrack | ByteTrack | ByteTrack (유지) |
| ID의 지위 | 안 씀 | 안 씀 | 정답(override) | 힌트(가산점) | **재료(tracklet 조각)** |
| 진짜 공 판별 | 채점 | 300px 게이팅+겹침 | id 우선+게이트 | 정지 공 감점 | **트랙 전체 채점** |
| 공 미검출 | 등속 외삽 | 외삽 최우선 | 외삽→carrier | 외삽→carrier | **보간(재등장 역산)** |
| 소유선수 | 없음 | 기하 겹침 | 채점식(DET-05) | 채점식 | **기하 겹침** (custom 방식) |
| 흔들림 억제 | 데드존 체인 | 데드존 체인 | 데드존 체인 | 데드존 체인 | **전역 경로 최적화** |

요구사항 커버리지:

| 요구사항 | 기존 4개 공통 한계 | 클립 2-패스 |
|---|---|---|
| 2. 프레임별 미탐지 | 외삽 = 추측 → 재등장 시 점프 | 양끝 실측 사이 **보간** → 점프 구조적으로 없음 |
| 4. 공 여러 개 | 프레임 단위론 진짜 공과 구분 불가 | 20초 궤적 단위 채점 (이동량·선수 상호작용·커버 시간) |
| 5. 장기 가림 | carrier 추측 유지 | 재등장 지점을 알고 소유선수 경유로 이동 |

기존 브랜치에서 흡수한 자산:
- **trackcrop-custom**: 기하 겹침 소유 판정(`공 중심 ∈ 선수 bbox+margin`) — 트랙 채점의
  "선수 상호작용" 신호이자 장기 가림 fallback.
- **trackcrop-hybrid**: 정지 공 배제 → 트랙 채점의 이동량 항으로 일반화.
- **feat/crop-live-preview**: detect(비싼 추론)/plan(순수 계산) 분리 + 검출 캐시 —
  검출은 한 번, 계획은 반복 실험하는 토대.

## 3. 클립 플래너(2-패스) 설계

검출(`DetectedSamples`)을 입력으로 받는 순수 계산 레이어. 두 패스로 나뉜다.

### 패스 1 — 공 트랙 확정 (`balltrack.py`)

1. **Tracklet 구성** — 공 검출을 track_id로 묶는다. 같은 id 안에 물리적으로
   불가능한 점프(속도 한계 초과)가 있으면 그 지점에서 쪼갠다 (id는 드물게 의심).
   id 없는 검출은 단독 tracklet.
2. **스티칭** — 시간순으로 조각을 연결한다. 앞 조각의 끝 위치+속도로 외삽한
   예측과 뒤 조각의 시작 위치가 (기본 허용 + 속도×gap) 안이면 같은 공으로 연결.
   시간이 겹치는 조각은 절대 연결하지 않는다 (동시에 보이면 다른 공).
3. **트랙 채점** — 후보 트랙마다:
   - 이동량 (총 경로 길이; 정지 공=관중석·프린트 공 배제 — hybrid 일반화)
   - 선수 상호작용 비율 (기하 겹침 — custom 방식)
   - 커버 시간 (클립 대비 관측 구간)
   최고점 트랙을 경기 공으로 채택. 최저 점수 미달이면 "공 없음" 클립으로 처리.
4. **흡수 병합** — 채택 트랙과 시간이 겹치지 않는 나머지 트랙 중 조건을 만족하면
   완화된 허용치로 병합 (장기 가림 후 재등장한 같은 공 회수).

### 패스 2 — 타깃 결정 + 경로 최적화

**타깃 결정** (`clip_planner.py`): 샘플 그리드 각 시점에
- 트랙 실측 → 공 위치. 트랙 내부 gap ≤ 한계 → **선형 보간** (추측 아닌 확정).
- 공+선수 군집이 한 화면에 들어오면 가중 중심 (기존 0.7/0.3 유지).
- 긴 gap·트랙 밖 → 소유선수(기하 겹침 기억) → 선수 군집(중앙값) → 직전 유지 → 960.

**경로 최적화** (`pathopt.py`): 크롭 중심 경로 c에 대해

```
J(c) = Σ w_follow·conf·ramp(|c−b| − dz)²   (데드존 밖 이탈 페널티)
     + Σ w_inside·conf·(c−b)²              (데드존 안 미세 인력 — 수치 안정용)
     + Σ w_vel·(Δc)² + Σ w_acc·(Δ²c)²      (팬 속도·가속 페널티)
```

를 IRLS(반복 재가중 최소제곱)로 최소화. 데드존·속도제한·스무딩 체인이 하던 일을
목적함수 하나로 통합 — "공 안 놓치기 vs 덜 흔들리기"가 페널티 비율로 직접 조절된다.
미래를 아는 최적화라 "곧 이동할 방향으로 미리 천천히 출발"이 자연스럽게 나온다.
마지막에 크롭 범위 클램프 + 최대 속도 하드 캡으로 스펙을 보장한다.

### 튜닝 노브 (`ClipPlanConfig`)

| 노브 | 의미 |
|---|---|
| `ball_max_speed_px_s` | tracklet 쪼개기/스티칭의 물리 한계 속도 |
| `stitch_max_gap_ms`, `stitch_base_px` | 조각 연결 허용 시간·거리 |
| `w_travel`, `w_interaction`, `w_span`, `min_track_score` | 트랙 채점 가중치·컷 |
| `possession_margin` | 소유 판정 bbox 마진 비율 |
| `interp_max_gap_ms` | 선형 보간을 허용하는 최대 gap |
| `w_follow`, `w_vel`, `w_acc` | 이탈 vs 흔들림 트레이드오프 |
| `dead_zone_width` | 무페널티 구간 폭 (기존 208 유지) |

## 4. 통합 계획

1. 이 브랜치: `balltrack.py`·`pathopt.py`·`clip_planner.py` + 테스트 (독립 모듈,
   기존 파이프라인 무변경 — 기존 경로와 A/B 가능).
2. feat/crop-live-preview의 detect/plan 분리가 머지되면 Lab에서 같은 검출 캐시로
   기존 계획 vs 오프라인 계획을 나란히 비교.
3. 지표(공 크롭 내 시간 비율, 팬 방향 반전 수, 최대 속도 위반)로 검증 후,
   탐지 단계 재검토 (predict+자체매칭 57% vs ByteTrack 44% — 스티칭 레이어가
   ID 품질 의존을 낮추므로 검출률 복귀 선택지가 열림).
